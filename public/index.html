How it works

From session code to synced clip

No separate recording setup for every player. One code gets the whole squad on the same clock.

01

Start a session

One player opens Peak-Abu and generates a session code.

02

Squad joins

Everyone else drops the same code into their own client. No configuration to match.

03

Play like normal

Each client quietly holds a rolling buffer of that player's own gameplay in the background.

04

Any player triggers it — a hotkey is all it takes. Every POV extracts the same window, at the same instant.

Under the hood

From game window to shared replay

Every clip follows the same five-stage path — whether it's one player grabbing a clutch moment or a full squad locking in a synchronized multi-POV save.

01 · capture
Local ring buffer
Each player's client silently records their game window into a rolling buffer — save it manually, or let auto-capture trigger it for you.
per player · local auto-capture · testing
02 · sync
Coordinated save
The server broadcasts a server-stamped timestamp to every connected client — locking every POV to the identical moment.
patent pending
03 · extract
Buffer extraction
Each client runs FFmpeg locally to slice the clip. Raw footage never leaves your machine unprocessed.
local · ffmpeg
04 · store
Cloud storage
Encoded clips upload directly to cloud storage. The server indexes them, then optionally renders a composite or AI reel.
DO Spaces · indexed
05 · share
Web player
A shareable link serves synchronized multi-POV playback in any browser — with timestamped Quick Comments over top.
shareable · no login

What's under the hood

Every feature earns its place

Built for five-stacks reviewing a scrim and for solo sessions that just need a clip out the door — not features a highlight tool "should" have.

Multi-POV capture

Every teammate's own game window is captured locally on their own machine — no one uploads raw footage they don't need to.

Coordinated save

A shared clock keeps every client's rolling buffer in sync, so one save extracts the identical moment from every POV — patent pending.

Server-side composite export

Want one combined file instead of juggling separate streams? Export a single stitched clip straight from the server.

AI highlight reels

Turn a full session into an edited reel automatically, then drop it straight into an editing app for a final polish pass if you want one — the model does the picking, you decide how far to take it.

Smart delivery

Playback is built to stay fast and light on bandwidth, whether you're reviewing one POV or scrubbing through all of them.

Free tier, no forced cloud costs

Keep everything local on the free tier — no surprise storage bills. Upgrade only when you actually want cloud-hosted, shareable replays.

Taken seriously, not bolted on

Security, built against real standards

Peak-Abu is developed against the same core categories used by modern secure-development frameworks like OWASP and Microsoft's SDL — not as a checkbox, but as an ongoing practice.

Input validation

Every input is treated as untrusted and validated server-side.

Authentication

Hashed credentials and secure session handling.

Access control

Permission checks enforced on every request, not just the UI.

Data protection

Encrypted in transit; sensitive data never logged.

Secrets management

No secrets in code — vaulted and environment-scoped.

Secure architecture

Minimal attack surface, internal APIs kept internal.

Dependency security

Libraries scanned and kept current, not left to rot.

Logging & monitoring

Auth events logged, anomalies watched for.
